# Phase 2 Plan 02: Importação Excel e Estados dos Cards

<objective>
Implementar leitura inicial de planilhas XLSX no navegador usando SheetJS local, com um módulo `js/importer.js` responsável por converter `File` em workbook metadata e `js/app.js` responsável por renderizar cards independentes de upload. O usuário deve conseguir carregar pedidos, contas a pagar e indicadores/metas opcional, vendo estados compactos e metadados básicos sem validação profunda, normalização, persistência ou dashboards reais.
</objective>

<requirements_addressed>
- `IMP-01`: usuário consegue selecionar a planilha de pedidos na página de upload.
- `IMP-02`: usuário consegue selecionar a planilha de contas a pagar na página de upload.
- `IMP-03`: usuário consegue selecionar opcionalmente a planilha de indicadores/metas sem bloquear o fluxo.
</requirements_addressed>

<threat_model>
## Ameaças e mitigações da fase

- **T-02-02: Leitura de arquivo fora da seleção do usuário.** O navegador só deve processar arquivos escolhidos via input. Mitigação: usar `<input type="file">`, `File.arrayBuffer()` ou `FileReader.readAsArrayBuffer(file)`, sem paths locais, `fetch` ou `XLSX.readFile`.
- **T-02-03: Confundir leitura com validação.** Marcar planilhas como válidas nesta fase criaria confiança indevida. Mitigação: usar copy `Lido`, não `Válido`; validar estrutura só na Fase 3.
- **T-02-04: Contaminar escopo com normalização.** Remover total rows, parar em `TOTAL`, calcular métricas ou persistir datasets pertence a fases futuras. Mitigação: retornar apenas metadados de workbook e contagem bruta.
- **T-02-05: Estado global frágil.** Erro em um upload não pode apagar outros cards nem bloquear indicador opcional. Mitigação: manter estado por fonte (`pedidos`, `contas`, `indicadores`) e calcular completude obrigatória apenas com pedidos + contas.
- **T-02-06: Acessibilidade em updates dinâmicos.** Mudança de status sem texto ou live region prejudica uso por leitor de tela. Mitigação: texto de status visível, `aria-live="polite"` e foco controlado apenas no atalho da topbar.
</threat_model>

- `docs/resume.md`

<action>
Criar `js/importer.js` como script clássico, sem `type="module"`, expondo `window.MoldeImporter`.

Implementar uma API com estes nomes concretos:

- `readWorkbookFile(file, kind)`
- `getWorkbookMetadata(workbook, file, kind)`
- `getPrimarySheetName(workbook, kind)`
- `countWorksheetRows(worksheet)`
- `listMonthlySheets(sheetNames)`

`readWorkbookFile(file, kind)` deve:

1. rejeitar quando `file` estiver ausente;
2. rejeitar arquivos sem extensão `.xlsx` ou `.xls`;
3. obter bytes com `await file.arrayBuffer()`;
4. chamar `XLSX.read(buffer)`;
5. retornar metadados usando `getWorkbookMetadata`.

`getWorkbookMetadata(workbook, file, kind)` deve retornar objeto com estes campos:

- `kind`
- `fileName`
- `importedAt`
- `sheetNames`
- `rowCount`
- `primarySheetName`
- `monthlySheetNames`

Regras por origem:

- `pedidos`: `primarySheetName` deve ser `workbook.SheetNames[0]` ou `null`.
- `contas`: `monthlySheetNames` deve filtrar abas que começam com `CONTAS ` e contêm `2026`.
- `indicadores`: `primarySheetName` deve ser `DADOS_PBI` quando existir; caso contrário, `workbook.SheetNames[0]` ou `null`.

Não implementar validação de colunas, datas, totais, fórmulas, status, métricas, normalização ou persistência.
</action>

- `js/importer.js` contém `arrayBuffer`.
- `js/importer.js` contém `XLSX.read`.
- `js/importer.js` contém `DADOS_PBI`.
- `js/importer.js` contém `CONTAS`.
- `js/importer.js` não contém `XLSX.readFile`.
- `js/importer.js` não contém `localStorage`, `indexedDB`, `Valor Final`, `Aguardando Aprovação`, `TOTAL` ou `situacao_grupo`.
- `node --check js/importer.js` sai com código 0.

```js
const importState = {
  pedidos: { status: "pending", metadata: null, error: "" },
  contas: { status: "pending", metadata: null, error: "" },
  indicadores: { status: "optional-empty", metadata: null, error: "" }
};
```

Implementar funções com estes nomes:

- `handleUploadSelection(kind, file)`
- `setImportStatus(kind, status, payload)`
- `getUploadCardView(kind)`
- `updateTopbarImportStatus()`
- `focusFirstPendingUploadCard()`

`handleUploadSelection(kind, file)` deve:

1. chamar `setImportStatus(kind, "reading")`;
2. chamar `window.MoldeImporter.readWorkbookFile(file, kind)`;
3. em sucesso, salvar `metadata` e marcar `status: "read"`;
4. em erro, salvar mensagem e marcar `status: "error"`;
5. não alterar outros cards.

Estados e copies obrigatórios:

- `Obrigatório`
- `Opcional não carregado`
- `Lendo arquivo`
- `Lendo arquivo...`
- `Lido`
- `Erro de leitura`
- `Selecionar planilha`
- `Substituir planilha`
- `Selecionar novamente`

O topbar deve refletir apenas obrigatórias:

- nenhum obrigatório lido: `Sem dados importados`
- um obrigatório lido: `1 de 2 obrigatórias lida`
- dois obrigatórios lidos: `Bases obrigatórias lidas`

Não persistir dados em `localStorage` ou IndexedDB nesta fase, exceto a chave de tema já existente `molde-theme`.
</action>
