# Phase 3 Plan 01: Schemas, Cleaners e Validadores

<objective>
Implementar a camada de validação no navegador: schemas de colunas/abas, regras de limpeza `NRM-01`/`NRM-02`, validadores `VAL-01`..`VAL-10` e orquestrador `MoldeValidation` que retorna relatório estruturado por planilha. Esta fase de código não altera a UI além de registrar scripts em `index.html` e expor workbook para validação.
</objective>

<requirements_addressed>
- `VAL-01`..`VAL-10`: regras de validação por pedidos e contas.
- `NRM-01`: excluir linhas de pedidos com `Pedido` vazio.
- `NRM-02`: parar leitura de contas no primeiro `TOTAL` por aba mensal.
</requirements_addressed>

<threat_model>
## Ameaças e mitigações

- **T-03-01: Confundir alerta com erro crítico.** Violações VAL devem bloquear; exclusões NRM são alertas. Mitigação: separar arrays `criticalErrors` e `warnings` no relatório.
- **T-03-02: Normalização prematura.** Campos derivados e persistência pertencem à Fase 4. Mitigação: não criar `situacao_grupo`, `status_pagamento`, IndexedDB ou export CSV.
- **T-03-03: Perder referência de linha Excel.** Achados sem linha/ID prejudicam auditoria. Mitigação: todo finding inclui `excelRow` e `businessId`.
- **T-03-04: Contaminação por totais.** Totais misturados distorcem validação. Mitigação: cleaners aplicados antes dos validadores.
</threat_model>

<action>
Criar `js/validators.js` expondo `window.MoldeValidators` com funções que retornam arrays de critical errors `{ ruleId, message, excelRow, businessId }`:

`validatePedidosStructure(headerIndex)` → `VAL-01` se faltar coluna obrigatória.

`validatePedidosRows(records)` implementa:

- `VAL-02`: `Situação`, `Cliente`, `Data Prevista` ou `Data Entregue` vazios (`Não definido` conta como vazio)
- `VAL-03`: data inválida; `Data Entregue` &lt; `Data de cadastro` quando ambas válidas
- `VAL-04`: `Math.abs((valorBruto - valorDesconto) - valorFinal) > 0.01`
- `VAL-05`: situação contém `Entregue` (case-insensitive) e `Valor Pendente > 0`

`validateContasStructure(monthlySheets, workbook)` → `VAL-06` para abas mensais ausentes ou cabeçalho sem colunas obrigatórias na linha 2.

`validateContasRows(records, sheetName, expectedMonth, expectedYear)` implementa:

- `VAL-07`: `VALOR`, `CLASSIFICAÇÃO`, `CATEGORIA` ou `CONTA` vazios
- `VAL-08`: `PAGO` indica pago (`SIM`, `Sim`, `S`, etc.) e `DATA PAG` vazia
- `VAL-09`: `DATA VENC` com mês/ano diferente do esperado da aba
- `VAL-10`: pares de `CATEGORIA` ou `CLASSIFICAÇÃO` com grafia similar após normalização (trim, lowercase, colapso de espaços; distância de Levenshtein ≤ 2 e strings diferentes)

Helpers obrigatórios:

- `parseBrazilianDate(value)` aceita serial Excel e `dd/mm/yyyy`
- `parseBrazilianNumber(value)` aceita número e string pt-BR
- `normalizeLabel(value)`
- `levenshtein(a, b)`
- `isPaidFlag(value)`
- `getBusinessIdPedido(record)` → `Pedido`
- `getBusinessIdConta(record)` → `FORNECEDOR` ou `DESCRIÇÃO`

Toda violação VAL vai para `criticalErrors`, nunca para `warnings`.
</action>

- `validateWorkbook(workbook, kind)` → relatório por source
- `validatePedidos(workbook)`
- `validateContas(workbook)`
- `validateIndicadores(workbook)` — apenas checagem leve: aba `DADOS_PBI` existe e tem cabeçalho; nunca retorna status que bloqueie fluxo global
- `buildReport(kind, criticalErrors, warnings, validRowCount)` calcula:
  - `status`: `invalid` se `criticalErrors.length > 0`; senão `valid_with_warnings` se `warnings.length > 0`; senão `valid`

Fluxo `validatePedidos`:

1. ler aba principal
2. validar estrutura `VAL-01`
3. converter linhas com `excelRow`
4. aplicar `MoldeCleaners.cleanPedidosRows`
5. validar linhas limpas
6. montar relatório

Fluxo `validateContas`:

1. listar abas mensais
2. validar estrutura `VAL-06`
3. para cada aba: parse, clean com `NRM-02`, validar `VAL-07`..`VAL-10`
4. agregar findings com `sheetName` no `businessId` quando útil

Estender `js/importer.js` com `readWorkbookBuffer(file)` retornando `{ workbook, metadata }` sem quebrar `readWorkbookFile`.
