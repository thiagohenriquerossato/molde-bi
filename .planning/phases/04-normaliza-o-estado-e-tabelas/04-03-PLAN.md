# Phase 4 Plan 03: Base de Dados, Tabelas Virtuais e Exportação CSV

<objective>
Implementar página `#base-dados` com abas Pedidos/Contas/Indicadores, tabelas com scroll virtual, ordenação, busca, destaque de inconsistências e exportação CSV do dataset filtrado.
</objective>

<must_haves>
- Abas com uma tabela por fonte
- Scroll virtual (não paginação clássica)
- Column visibility persistida em localStorage
- Linhas com alertas destacadas (TBL-02)
- CSV exporta apenas linhas filtradas (FLT-05)
</must_haves>

<threat_model>
## Ameaças e mitigações

- **T-04-08: Exportar dataset completo ignorando filtros.** Mitigação: export chama `applyFilters` antes de `exportCsv`.
- **T-04-09: Tabela lenta com milhares de linhas.** Mitigação: virtual scroll renderiza janela visível apenas.
- **T-04-10: Dashboards fake na Base de Dados.** Mitigação: só tabelas, sem KPI cards com números agregados.
</threat_model>

## 1. Criar `js/tables.js`

<task>
id: `04-03-01`
type: `feature`
files:
- `js/tables.js`

<read_first>
- `docs/TABLES.md`
- `.planning/phases/04-normaliza-o-estado-e-tabelas/04-UI-SPEC.md`
- `.planning/phases/04-normaliza-o-estado-e-tabelas/04-CONTEXT.md`
- `js/filters.js`
</read_first>

<action>
Criar `window.MoldeTables`.

Definir `COLUMN_SETS` para `pedidos`, `contas`, `indicadores` com:
```js
{ key, label, defaultVisible: boolean, type: "text"|"currency"|"date"|"badge", getValue(row) }
```

Colunas default visíveis conforme `04-UI-SPEC.md`.

Funções:
- `getColumnVisibility(kind)` / `setColumnVisibility(kind, keys)` usando localStorage `molde-cols-{kind}`
- `sortRows(rows, sortKey, direction)`
- `renderVirtualTable(container, { rows, columns, sort, onSort, rowClassFn })` — viewport ~480px, row height 36px, render slice based on scrollTop
- `formatCell(value, type)` — moeda pt-BR `R$`, datas `dd/MM/yyyy`
- `exportCsv(rows, columns, filename)` — BOM `\uFEFF`, separator `;`, header labels

`rowClassFn`: retorna `data-table-row-warning` se `row.validationAlerts?.length > 0`.

Badge na coluna status/id: primeiro alerta `validationAlerts[0].message` com `badge-warning`.
</action>

<acceptance_criteria>
- `js/tables.js` define `window.MoldeTables`.
- Contém `renderVirtualTable` ou `virtual`.
- Contém `exportCsv`.
- Contém `data-table-row-warning` ou `row-warning`.
- Contém `COLUMN_SETS` ou column defs para pedidos/contas.
- `node --check js/tables.js` exit 0.
</acceptance_criteria>

<verify>
```sh
test -f js/tables.js
rg "window\\.MoldeTables|renderVirtualTable|exportCsv|data-table-row-warning|COLUMN" js/tables.js
node --check js/tables.js
```
</verify>
</task>

<action>
Adicionar `render: renderBaseDadosPage` na rota `base-dados` em `routes`.

`renderBaseDadosPage`:
- Se `!appState.dataset` → empty state existente
- Senão: tablist `Pedidos | Contas a pagar | Indicadores` (`data-base-tab`)
- Toolbar: contagem filtrada, botão `Colunas`, `Exportar`
- Aplicar `MoldeFilters.applyFilters(dataset[kind], kind, filterState)`
- Renderizar via `MoldeTables.renderVirtualTable`
- Ordenação client-side ao clicar header
- `Exportar`: filename `molde-{tab}-{date}.csv` com rows filtradas e colunas visíveis

CSS em `app.css`:
- `.base-dados-tabs`, `.table-virtual-viewport`, `.data-table-row-warning`
- Sticky header dentro do viewport

`index.html`: `<script src="js/tables.js" defer>` antes de `app.js`.

Re-render tabela quando `filterState` muda (listener ou chamada após filter updates).
</action>
